## 2. Vai trò của bạn

Bạn là Lead Agent, có trách nhiệm:

1. Phân tích toàn bộ yêu cầu.
2. Thiết kế kiến trúc hệ thống.

## 3. Nguyên tắc quan trọng

* Chỉ sử dụng API chính thức của từng nền tảng.
* Không scrape trái phép.
* Không dùng bot giả lập hành vi người dùng.
* Không tự động like, share hoặc comment nếu API chính thức không cho phép.
* Không lưu access token ở frontend.
* Không hard-code secret key.
* Không commit file `.env`.
* Tất cả token phải được mã hóa trước khi lưu database.
* Phải hỗ trợ token refresh khi nền tảng cho phép.
* Phải xử lý token hết hạn, tài khoản bị ngắt kết nối và API rate limit.
* Phải có audit log cho các hành động quan trọng.
* Phải có hệ thống phân quyền người dùng.

## 6. Thiết kế tích hợp nền tảng

Tạo interface chung:

```ts
interface SocialPlatformAdapter {
  connectAccount(): Promise<void>;
  refreshToken(): Promise<void>;
  getAccountProfile(): Promise<SocialAccountProfile>;
  publishPost(input: PublishPostInput): Promise<PublishResult>;
  deletePost?(postId: string): Promise<void>;
  getPosts(params: SyncPostsParams): Promise<PlatformPost[]>;
  getPostMetrics(postId: string): Promise<PostMetrics>;
  getComments(postId: string): Promise<PlatformComment[]>;
  replyToComment?(
    commentId: string,
    message: string
  ): Promise<CommentReplyResult>;
  deleteComment?(commentId: string): Promise<void>;
  hideComment?(commentId: string): Promise<void>;
}
```

Tạo adapter riêng:

* FacebookAdapter
* InstagramAdapter
* PinterestAdapter
* YouTubeAdapter
* TikTokAdapter

Không đặt logic của từng nền tảng trực tiếp trong controller hoặc UI.

Mỗi adapter phải có:

* Validation
* API client
* Token handling
* Error normalization
* Rate limit handling
* Retry policy
* Logging
* Mapping dữ liệu platform sang unified schema

## 9. Trạng thái bài đăng

Sử dụng state rõ ràng:

```ts
type PostStatus =
  | "DRAFT"
  | "SCHEDULED"
  | "QUEUED"
  | "PROCESSING"
  | "PUBLISHED"
  | "PARTIALLY_PUBLISHED"
  | "FAILED"
  | "CANCELLED";
```

Khi đăng nhiều nền tảng:

* Nếu tất cả thành công: `PUBLISHED`
* Nếu một số thành công và một số thất bại: `PARTIALLY_PUBLISHED`
* Nếu tất cả thất bại: `FAILED`

Mỗi platform post phải có trạng thái riêng.

## 21. Quy tắc thực thi

* Trước khi sửa file, hãy đọc cấu trúc repository hiện tại.
* Không xóa code đang hoạt động nếu chưa đánh giá.
* Mỗi thay đổi lớn phải có lý do.
* Sau mỗi module, chạy lint, type-check và test.
* Khi gặp lỗi, tìm nguyên nhân gốc thay vì che lỗi.
* Không bỏ qua TypeScript error.
* Không tắt ESLint rule chỉ để build thành công.
* Không dùng dữ liệu giả để tuyên bố integration đã hoạt động.
* Không tuyên bố hoàn thành API nếu chưa kiểm thử.
* Không tự tạo credential giả.
* Với secret chưa có, sử dụng placeholder trong `.env.example`.
* Mọi chức năng phụ thuộc xét duyệt ứng dụng phải được đánh dấu rõ.
